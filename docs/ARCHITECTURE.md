# Architecture and project context

Browser game **Creepypasta Explorator** (repo `liminalspaces`; called Liminal Spaces up to 0.18.0): a first-person walk through two worlds — an endless, procedurally generated building (liminal spaces), rendered by default at low resolution with a pixel-art filter, and **The Great Path**, a hand-laid multi-level 3D world built from the story “Rudon's Plane” (see [`GREAT_PATH.md`](GREAT_PATH.md)), rendered finer. Since 0.18.0 both run on the same cell engine (`js/story/`: grid, mesher with baked light, PBR materials, worker, walker); each game has its own graphics profile. No dependencies except three.js (vendored locally), no network requests in single player.

Published at: repo <https://github.com/michalstankiewicz4-cell/liminalspaces>, site <https://michalstankiewicz4-cell.github.io/liminalspaces/> (GitHub Pages, workflow `.github/workflows/static.yml`). Engine origin: <https://github.com/michalstankiewicz4-cell/VS> (Capital Quarantine).

## Modes and flow (`js/core/app.js`)
`menu` (start screen: a slowly turning view of a fixed seed, `MENU_SEED`) → Single Player: New walk (random seed) / Continue walk (last seed and position from the save) / walk a typed seed (`seedFrom`: digits are used as the number, other text is hashed) → `play`.
**Esc** in `play` pauses (`paused = true`, pointer lock released) and opens the pause menu (Resume / Invite player — host only / Options / Quit to main menu); inside Options or Invite it goes back; on the pause menu it resumes. Losing pointer lock (the browser's own Esc handling) also pauses; a guard (`lockPauseAt`) stops the same Esc from immediately resuming. In `menu` mode Esc goes back one screen.
`startWalk(seed, spawn, session)` resets the world, places the player, preloads all chunks in view, hides the menu and requests pointer lock.

## World generation (`js/world/gen.js`)
- Units: metres. `CELL = 4` m, `N = 8` cells per chunk, `CHUNK = 32` m, wall height `H = 3`, thickness `T = 0.2`.
- **Determinism**: every chunk is built only from `(seed, i, j)` with `mulberry32(hash4(seed, i, j, salt))`; global features (zones, borders, lights, water) use stateless `rand4`. No `Math.random()` here. An LRU cache keeps 600 chunks.
- **Zones**: staggered 3×3-chunk regions (each region row is shifted by a random 0–2 chunks so the borders do not form a grid); weighted random theme per region (offices 40 %, corridors 22 %, garage 20 %, pools 18 %); the spawn region is always offices. Per-theme parameters in `THEME` (border openings, braid, rooms, lintels, ambient light, tint, light layout).
- **Walls** on cell edges: `east[x+z*N]` / `south[x+z*N]`. The last column/row is the border with the next chunk, generated by `border(i, j, axis)` from both chunks' themes and the chunk coordinates — both sides always agree, and every border has at least one opening.
- **Offices/corridors**: all internal walls up, then a randomised DFS spanning tree (corridors prefer to keep going straight), then braiding (extra openings) and open rooms; carved openings may get a lintel (`lintE`/`lintS`, from `LINTEL = 2.3` m to the ceiling). **Garage/pools**: open halls with a few wall pieces and pillars (`PILLAR = 0.7`); pools get water blobs.
- **Lights**: per cell `0` none, `1` on, `2` flickering, `3` dead (`lightOf`). Garage: only every other cell, many dead.
- **Oddities** (`ODDITIES`): at most one per chunk (≈42 % of chunks); kind filtered by theme, rare kinds less likely; `wall` kinds stick to the cell's east/south wall when there is one. `oddityPos()` gives the world position.
- **Collision**: `solidsNear(x, z)` returns AABBs of walls in the 3×3 cells around a point, plus pillars and solid oddities. Lintels are above head height and do not collide.
- **Reachability check** (in a throwaway script during development): BFS over cells for several seeds reaches all cells in a 64×64-cell window.

## The endless world on the cell engine (since 0.18.0)
Generator chunks (8×8 cells of 4 m) and engine chunks (64×64 cells of 0.5 m) are both 32 m with the same origin, so `endless/layout.js` paints one generator chunk into exactly one engine chunk the first time any cell of it is queried (`grid.lazyChunk`; in that mode every painted chunk exists). A wall on the east/south edge of a 4 m cell closes the last 0.5 m strip of that cell; every lattice corner touched by a wall closes the 0.5 m cell north-west of it (so L and T joints and free wall ends have no notches); lintels are open strips with a 2.3 m ceiling; pillars are 1 m squares; ceiling height 3 m. Pools are sunk 0.4 m (one step) with a `poolWater` surface prop. Lights: one per 4 m cell centre (`panel` offices/pools, `bulb` hotel corridors, `tube` garage; flickering and dead ones from the generator). Materials: the engine's PBR set plus `hotelWall`, `hotelCarpet`, `poolTile`, `garageFloor`. Zones (`ZONES` in `endless/layout.js`) set ambient light, tint, fog colour and distance. Seeds give the same plan as before 0.18.0; walls are thicker (0.5 m instead of 0.2 m) and sit on one side of the cell edge.
The old renderer of this world (`world/chunks.js`, `mesh.js`, `textures.js`, `oddities.js`, `index.js`, `player.js`) was removed; the text below on chunk meshes and the player describes it for history.

## Chunk meshes and lighting (before 0.18.0)
- One `Group` per chunk with one mesh per material bucket (`<theme>:wall|floor|ceil`, `door`, `prop`, `glow`, `lightOn`, `lightFlicker`, `lightDead`, `water`). Faces are subdivided (~1.4 m segments, floors/ceilings 3×3 per cell) so vertex lighting has enough resolution.
- **Baked lighting**: `lightGrid()` samples light state, ambient and tint for the chunk plus a 2-cell margin (so lighting is seamless across chunk borders); `makeShade()` returns per-vertex colour = ambient (bilinear) + Σ light power / (1 + d²/2.4²) over a 5×5 cell window, times the zone tint. Materials are `MeshLambertMaterial` with `vertexColors`, lit only by an `AmbientLight` of intensity π (so final colour = texture × vertex colour). The flashlight (`SpotLight` on the camera) adds real light on top.
- **Flicker**: all flickering panels share `materials.lightFlicker`, whose colour is modulated in `world.update()`; the tube buzz in audio follows it when you stand under one.
- Streaming (`world.stream`): chunks within `viewDist` (1–3) are built nearest first, at most one per frame (~10 ms each); chunks beyond `viewDist + 1` are disposed. Fog distance follows the view distance; fog colour follows the zone.

## Player (before 0.18.0; now the engine's walker, `story/walker.js`)
Eye height 1.6 m, radius 0.3, walk 3 m/s, run 5.4 m/s, jump 5.2 m/s, gravity 18 m/s². Movement is sub-stepped (≤ 0.2 m) and resolved with two passes of circle-vs-AABB push-out. Yaw/pitch from mouse movement (`sens` setting, optional Y inversion) and the turn keys. Footsteps fire every half head-bob cycle and pick the sound by zone (or a splash in water).

## Mouse look
Pointer lock is requested with `{ unadjustedMovement: true }` (raw input, falls back when unsupported). `Input` drops the first two events after a lock change and single events far larger than the recent average (Chrome pointer-lock spikes).

## UI and i18n
All UI is built with `h(tag, props, ...kids)` (`js/ui/dom.js`) — no `innerHTML`. Static text uses `bind(el, key)` / `tx(key)` and follows the language automatically; dynamic text (HUD, pause info) is recomputed with `t(key, params)`. Add a language: new dictionary in `js/i18n/`, register it in `index.js` (`dicts`, `LANGS`) and in the settings sanitiser. Missing keys fall back to English, then to the key itself.
Screens (`js/ui/menu.js`, `js/ui/multi.js`): `main`, `single`, `multi`, `host`, `join`, `room`, `pause`, `options`, with a small history stack (`go`/`back`). Each screen may have an `onShow` refresher. Options tabs (`js/ui/options/`): Graphics, Controls, Mouse, Audio, Language, Privacy & data.

## Settings (`js/core/settings.js`)
Stored in `localStorage` key `ls:settings:v1`: `v` (format version, 4), `lang`, `gfx`, `gfxPath` and `gfxTumi` — one graphics profile per game (the endless world, the Great Path) with the same fields and ranges, each with its own defaults: pixelH (100–720), levels (3–64), dither, edge, edgeW (outline thickness 0–2 in steps of 0.1), bright, fov (default 60°), viewDist, headBob, grain (endless off, path on), round (corner radius 0–24 cm, default 12), cove (0–20 cm, default 8), scan (scan lines), crt (CRT screen; both default off, done in the pixel pipeline's final pass); `gfx.showFps` is shared, `mouse` (sens, invertY), `audio` (volume, steps — footstep volume, default 50 %, hum, scratch), `hud.show`, `net` (name, stun), `keys` (action → two `KeyboardEvent.code` slots). Everything passes through `sanitize()` (clamps, whitelists, a key code can be used by one slot only; `Escape` is reserved; names are filtered by `cleanName`). Change settings only via `settings.update(draft => …)`.
Key actions (`js/input/bindings.js`): moveFwd/Back/Left/Right, turnLeft/Right, sprint, jump, flashlight, toggleHud.

## Rendering (`js/render/pixel-pipeline.js`)
Unchanged from Capital Quarantine: scene → `WebGLRenderTarget` of height `pixelH` (default 200 px) with a `DepthTexture` → full-screen shader: brightness, quantisation to `levels` with 4×4 Bayer dithering, outlines from depth differences (perspective depth is linearised), vignette. Defaults here are tuned for first person (outline 0.6, brightness 1.15, FOV 60°).

## Audio (`js/audio/audio.js`)
Everything is synthesised: a looping noise buffer through filters (room tone, water, garage rumble), a 60 Hz sine + filtered 120 Hz saw (hum/buzz), short filtered noise bursts (footsteps, landing, flashlight click), two sine tones (find chime). The context starts on the first click (autoplay rules). Zone changes cross-fade the mix.

## Multiplayer (`js/net/`)
**Switched off for now** (0.18.0: the endless world moved to the cell engine; the Multiplayer button is disabled until it is fixed). See [`MULTIPLAYER.md`](MULTIPLAYER.md). In short: the session shares only the seed and poses; transports are WebRTC DataChannels (manual copy/paste signalling, star topology through the host) or BroadcastChannel for same-browser rooms; every message is validated.

## The Great Path world (`js/story/`)
- **Cells**: `CS = 0.5` m, chunks of 64×64 cells (32 m). A cell is closed (solid) or open with its own floor and ceiling height. Everything 3D comes from differences between neighbours: walls (open↔closed), risers (floor steps), headers (ceiling steps), so drops, podiums, windows, lintels, tunnels and hanging blocks need no special code. Chunks never painted are closed.
- **Layout** (`layout.js`) paints rectangles (`room`, `door`, `solid`, `where` predicates), places props, notes and skylights, then lamps on per-zone grids (some dead, some flickering). The Great Path and the West Path are painted per 32 m column on demand (`grid.lazy`, with a guard against recursive painting), so they never end.
- **Meshing** (`mesher.js`): one chunk at a time, with lighting baked into vertex colours: zone ambient × tint, lamps and skylight bounce with wrap Lambert, falloff and occlusion (2D march through cells respecting floor/ceiling heights), direct sun squares under skylights, and AO from blocked samples and closeness to floor/ceiling. Materials are `MeshStandardMaterial` with procedural maps; the scene has an `AmbientLight` of π (so colour = albedo × baked light), a small PMREM environment for reflections, and the flashlight `SpotLight` with shadows. **L** (work lights) raises ambient and adds a hemisphere light.
- **Rounded edges**: in `meshChunk`, full-height wall runs that end at a convex corner stop `round` (default 12 cm, from `ctx.round`, set by `setRounding`) short and a quarter round (`Emitter.sweep`) with floor/ceiling fans (`Emitter.fan`) closes the corner (emitted by ±x walls only, once per corner); full walls get coves (`ctx.cove`, default 8 cm) at the floor (unless skirted) and the ceiling, revolved around convex corners (`Emitter.patch`). Colliders stay square.
- **Streaming**: chunks within 3 (radius) around the player. Meshing runs in a module Web Worker (`js/story/worker.js`, its own copy of the deterministic layout; buffers are transferred back and turned into meshes by `groupFromBuffers`), two chunks in flight; the 3×3 chunks around a spawn are built on the main thread. Without a worker everything falls back to the main thread. Prop colliders are collected in a dry run when needed (`prepare`).
- **Procedural detail**: wear decals (atlas: water stain, scuff, mould, crack) placed by hash on walls (every ~2.5 m, chance per material) and floors (per 2 m cell); rare anomalies and clutter painted by `layout.js` (per path column, per dense room).
- **Collision** (`blocked`, `support`): the walker's 0.54 m box against cells (closed, floor above the step height, ceiling below head) and prop boxes; step-up up to 0.45 m; gravity and falling; the layered gate adds temporary colliders.
- **Rendering**: `PixelPipeline` with `tone: 1` (ACES) and grain; with “detailed rendering” on, the render height is 360–720 px with 40 colour levels and light dithering.
- **Zones and journal**: each cell has a zone; entering a new one shows its name and story timestamp and adds it to the journal; cells seen (line of sight, 15 m) are drawn on the map and stay revealed (saved in `ls:pathmap:v1`). The full map opens framed on all explored chunks (`seenBounds`).
- **Notes**: canvas textures from i18n keys (`gp.n.*`), re-drawn on language change; looking at a note within 2.2 m shows it large in the HUD.
- **Skylights**: `sunAt(x, z)` (sun strength in a sun square) drives the exposure (`sun` in `core/path-mode.js`, 0..1, +sun/14 per second in the light, −1/5 per second in the shade) and the pipeline's `heat` uniform (shimmer, warm tint, bleach, burn vignette); above 0.6 the walker slows. Scratching (`story/audio.js`): its own `AudioContext`, synthesised strokes/taps/knocks through a glass low-pass and an HRTF `PannerNode` at a skylight chosen by `pickSkylight`; the listener follows the camera; every 25–60 s on the paths, 70–150 s elsewhere; `scratchVisual` shows the shape on the glass and dims that beam. Setting `audio.scratch`.
- **Guide** (`route.js`): `STEPS` with story timestamps; BFS on 0.5 m cells in a box around the player and the target (open, ≥1.8 m clearance, step up ≤0.45 m, drops allowed); recomputed when you leave the route or the step changes; up to 14 instanced chalk arrows along the next metres; HUD arrow from `heading()`; the map draws the route.
- **Sound** (`audio.js`): one `AudioContext`; beds per zone group cross-faded, three convolution reverbs (generated impulses) mixed per space; emitters registered by `layout.js` (props `funnel`, `station`, `vent`, `factory`, `machine` + mine drips) become positional loops/timers within 22 m; footsteps from the floor material under the walker (`walker.onStep`).
- **Events** (`events.js`): a timer scaled by `ZONE_LEVEL`, cooldown, last three events not repeated; effects through `story.setPower` (ambient light and lamp materials), `story.particles` / `story.flash` (one reused point light), `pipe.glitch` / `pipe.fear` uniforms, camera shake, `hand.setOn`. Setting `story.events`.
- **Statues** (`statues.js`): one tableau per guide step (`TABLEAUX`: figures with pose, size, hair, robe, held items); capsules/spheres/boxes in a joint hierarchy, a stone `MeshStandardMaterial` lit by `lightAt` at the spot, `LineDashedMaterial` outlines from `EdgesGeometry`; geometry and outlines are cached by size and shared; groups are added within 45 m and removed beyond 60 m; one collider box per figure (`story.addSolids`). Brass plaques on pedestals are placed by `layout.js` (`PLAQUES`).
- **Flashlight view model** (`hand.js`): a lathe torch body plus grip, rings, lugs, bezel and lens; `fit(fov)` scales it so it keeps its size and place on screen at any field of view; `setLight` darkens it in dark places.
- **Journey (part 2)**: `journey.js` paints the east side per column: the layout wraps the grid so every paint/prop/sign/light is clipped to the column being painted (`clip` in `layout.js`), so the same authoring code runs once per column and only keeps its slice. Cells flagged `F.OUT` are open to the sky (no ceiling; only a 0.6 m roof edge above lower neighbours; used for the ocean view and the stair holes). Zones can set `far` (fog distance), `night` (starry skylight glass) and `skyGlow`. Cells flagged `F.NOFLOOR` are walkable but draw no floor (the glass path and the grate: the water, the abyss and their side walls come from `water.js`). Invisible colliders are props with `{ solid: true, hide: true }` boxes (the opening onto the ocean). The walker (`walker.js`) stoops, crouches and crawls by itself (body heights 1.75 → 0.62 m) where the ceiling comes down, and its `world` ({ `blocked`, `support` }) is swapped for the surface's. `core/path-mode.js` switches scenes and worlds when you climb out of a stair hole (`journey.holeAt`), handles **E** (`use`), the inscription and the ending.
- **Teleport**: from the map journal (zone label positions) or by double-clicking an explored open cell.
- **Save**: `progress.path` in `ls:save:v1` — `{ x, z, yaw, seen: [zone ids], step }`. The story starts at the gate (`STARTS.gate`), as in the film.

## The caves of Tumithak (`js/caves/`, since 0.19.0)
The engine's exception for natural geometry: instead of the cell grid, a signed distance field `f(x, y, z)` (> 0 rock). Tubes are arched profiles (rounded box: large top radius, small bottom radius, so floors are flat) along a floor line; paths are Catmull-Rom curves cut into ~3 m tubes; shafts are vertical cylinders with a ladder on the east wall (the way on leaves eastwards at the top); caverns are ellipsoids with a floor; side caves only climb away from where they start (where they cross a tunnel they open its ceiling, never its floor). The union is a smooth minimum; noise displacement is per primitive (`amp`: glassy carved corridors ≈ 0.035, caves up to 0.9) and calmer near the floor. Chunks are 16 m cubes meshed by surface nets on a 0.5 m grid (edges owned by one chunk, so no seams); rock does not cast shadows (the beam comes from the eye). Walker: `blocked` samples the field over the body box, `support` scans down for air above rock, `ladder` returns the ladder within reach (the walker then climbs: W up, S down, held in place at the rungs). Reachability is checked with a BFS over standable 0.5 m spots (all ladders and places on the route reachable from Loor). The Surface (the end of chapter 6) is part of the same field: rock is where the caves are not and below `ground(x, z)` (gently uneven dust with the shallow pit of the exit), meshed out to ~330 m; zones may carry a coloured ambient (`ambC`), a low sun (`sun`: direction and colour, Lambert in the baked light) and a far tint (`grass`, blended in by distance from the pit). The sky is a shader dome (sunset, drifting clouds), the trees, the towers of the shelks (vertex-coloured by the sun) and their cables are plain meshes. Settings profile `gfxTumi`; save `progress.tumi` = { x, y, z, yaw, seen }.

## Persistence (localStorage)
- `ls:save:v1` — `{ v (save format, `SAVE_VERSION` = 2), game (version that wrote it), dist, odd, last: { seed, x, z, yaw }, path: { x, z, yaw, seen } }` (total metres walked, oddities found, last single-player walk; saved every 5 s while walking, on pause/quit and on page unload)
- `ls:settings:v1` — settings
- `ls:tumimap:v1` — explored 4 m cells of the caves of Tumithak (`"x,y,z"` keys) for the 3D map
- `ls:pathmap:v1` — explored map of the Great Path: `{ "ci,cj": base64 bitset of the chunk's 64×64 cells }` (saved with the walk when something new was seen; restored when the world is built)
Storage errors are swallowed (private mode etc.).

## Privacy and security
- CSP in `index.html`: `script-src 'self'`, `connect-src 'self'`, no external scripts/CDNs, no `eval`/`innerHTML`, no API keys. WebRTC is not covered by `connect-src`; it only starts from the multiplayer screens.
- No statistics, analytics or telemetry. Multiplayer sends name, position and direction to the connected players only. The public STUN server is opt-in.
- Incoming messages: max 4000 characters, JSON object with a string `t`, numbers checked for finiteness and range, ids must match `^[a-z0-9]{1,12}$`, names filtered; invite/reply codes have a prefix (`LS1.`), a size limit and a type check.

## Versioning (standing rule)
Besides the release `VERSION`, `js/version.js` holds `VERSIONS` — one per part: `menu` (start screen, menus, options, HUD shell), `endless`, `path` (Rudon's Plane); bump the parts a push changes and name them in the changelog entry; `tools/check-version.mjs` refuses a part going down. The save and the settings carry a format version; `migrate()` in `core/app.js` (save) and `sanitize()` in `core/settings.js` (settings) bring older data up to date — bump the format version and add a step there whenever the meaning of saved data changes. On start the app fetches `js/version.js` (no cache) and, if a newer version is published, the menu shows a reload notice.
Every push to `main` is a new semver version: bump `js/version.js`, add an entry at the top of `CHANGELOG.md`, run `node tools/check-version.mjs`, then push. The owner creates `vX.Y.Z` tags in GitHub Releases. Changes to world generation change every seed — mention it in the changelog.

## Testing (headless)
Playwright (Python) with Chromium and `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist` gives working WebGL2 without a GPU. Serve the folder with `python -m http.server`, open the page and get the app with `(await import('/js/main.js')).default` (it exposes `world`, `player`, `camera`, `settings`, `progress`, `session`, `mode`, `paused`, `startWalk(seed, spawn)`, `pause()`, `goMenu()`…). **Stub pointer lock** with an init script (`HTMLCanvasElement.prototype.requestPointerLock = () => Promise.resolve()`): a granted pointer lock in headless Chromium drops the frame rate to ~2 fps. Listen to `pageerror` and `console` errors. Scope button selectors to `.screen:not([hidden])`. WebRTC works between two browser contexts in one headless browser without STUN; same-browser rooms need two pages in the same context. For the Great Path, `A.startPath('gate')` and wait for `A.kind === 'path'`; `A.story`, `A.walker`, `A.path` (the mode: `statues`, `loadedCount`…), `A.teleport(x, z)` are exposed. SwiftShader is slow (a chunk takes ~50–100 ms to mesh there), so teleport with `walker.place()` + `story.preload()` rather than walking.
